# AIDEX Django Model Mapping

## Introduction

This document maps the AIDEX database design to Django models.

The purpose of model mapping is to clearly identify which database table is represented by which Django model and how different models are connected using relationships.

---

## Main Model Mapping

| Database Entity | Django App | Django Model | Database Table |
|---|---|---|---|
| Users | accounts | User | accounts_user |
| Cases | cases | Case | aidex_cases |
| Evidence | evidence | Evidence | aidex_evidence |
| Reports | reports | Report | aidex_investigation_reports |

---

## User Model Mapping

### Django Model

```text
accounts.User
```

### Purpose

The User model stores authentication and official user information.

### Main Fields

- Username
- Password
- Full Name
- Email
- Phone Number
- Department
- Badge ID
- Role
- Profile Photo
- Account Status
- Date Joined
- Last Login

### Relationships

One User can:

- Create multiple Cases
- Be assigned multiple Cases
- Upload multiple Evidence items
- Verify multiple Evidence items
- Generate multiple Reports
- Review multiple Reports
- Approve multiple Reports

## Data Integrity Rules

- Every Case must have a valid creator.
- Assigned Investigator may be optional.
- Every Evidence item must belong to a valid Case.
- Every Evidence item must have a valid uploader.
- Evidence verification user may be optional until review.
- Every Report must belong to a valid Case.
- Every Report must have a valid generator.
- Report reviewer and approver may be optional until review.
- Protected relationships use PROTECT where deletion could damage records.
- Optional relationships use SET_NULL where history must be preserved.

## Expected Result

The model mapping provides a clear connection between AIDEX database entities, Django applications, model classes and database tables.

It supports secure relationships, structured data storage and future module integration.
