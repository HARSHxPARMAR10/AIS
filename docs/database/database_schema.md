# Database Schema

## Introduction

The Database Schema defines the structure of all major database tables used in the AIDEX (AI-Powered Cyber Crime Evidence Management System). Each table stores a specific type of information required for managing cyber crime investigations, digital evidence, reports, and user activities.

The schema is designed using MySQL and will later be implemented using Django ORM.

---

# Table 1: Users

Purpose:
Stores information about every authenticated user of the system.

Fields:

- User ID (Primary Key)
- Full Name
- Username
- Email Address
- Password
- Phone Number
- Department
- Badge ID
- Role
- Profile Photo
- Status
- Created Date
- Updated Date

---

# Table 2: Cases

Purpose:
Stores all cyber crime case information.

Fields:

- Case ID (Primary Key)
- Case Number
- Case Title
- Case Description
- Crime Category
- Investigation Status
- Assigned Investigator
- Created Date
- Updated Date

---

# Table 3: Evidence

Purpose:
Stores digital evidence related to cyber crime cases.

Fields:

- Evidence ID (Primary Key)
- Case ID (Foreign Key)
- Evidence Type
- Evidence File
- File Hash
- Uploaded By
- Upload Date
- Verification Status

---

# Table 4: Reports

Purpose:
Stores investigation reports generated by investigators.

Fields:

- Report ID (Primary Key)
- Case ID (Foreign Key)
- Generated By
- Report Title
- Report Description
- Generated Date

---

# Table 5: Audit Logs

Purpose:
Stores all user activities for security and accountability.

Fields:

- Log ID
- User ID
- Action Performed
- Date
- Time
- IP Address
- Status

---

## Conclusion

The database schema provides a structured way to store and manage all cyber crime investigation data. It ensures data consistency, integrity, and efficient retrieval while supporting future system expansion.
